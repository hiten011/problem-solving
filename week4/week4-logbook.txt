Problem: [MonsterValley2]

Design Thinking:
At each position, I considered two options: either bribe the monster or not. This naturally led me to design a recursive function to explore all possible choices.

Troubleshooting:
While implementing this, I realized that at each step I only needed to keep track of the minimum number of coins required to reach the end, which simplified the state management in the recursion.

Reflection:
The total time complexity of this solution is O(2^N). I learned how recursion can help model choice-based problems, but also how its exponential complexity makes it inefficient for larger inputs.


Problem: [UnsealTheSafe]

Design Thinking:
Initially, I wrote a recursive function to calculate the total number of possible combinations. However, this resulted in a Time Limit Exceeded (TLE) because the time complexity was O(N × 10^N).

Troubleshooting:
To optimize, I applied memoization, which reduced the complexity to O(N × 10 × 10). While this worked, I realized the problem could be solved more efficiently using dynamic programming. By building the solution bottom-up, I successfully implemented a DP approach that kept track of valid moves for each digit and state.

Reflection:
The final DP solution achieved O(N × 10 × 10) time complexity with efficient space usage. Through this problem, I learned how recursive solutions can often be transformed into DP by identifying overlapping subproblems and transition states.


Problem: [PaternityTest]

Design Thinking:
I approached this problem using a greedy strategy. First, I matched all positions in the child’s DNA with the mother’s DNA. Any positions that did not match the mother must match the father, otherwise the candidate father is invalid. After that, I only needed to check positions where the child’s DNA matched both the mother and the candidate father. These positions can be considered as possibly belonging to the father. If the count of such positions is at least half of the child’s DNA length (n / 2), then the man can be considered a possible father.

Troubleshooting:
The main challenge was ensuring that unmatched positions between the mother and child were strictly enforced to match with the candidate father. Initially, I overlooked cases where overlaps between mother and father DNA could confuse the count, but after adjusting the logic to decrement the overlap count properly, the solution worked as expected.

Reflection:
This problem reinforced how greedy checking combined with careful case handling can solve string-matching problems efficiently. By structuring the logic step by step, I was able to avoid unnecessary computations and ensure correctness.


Problem: [FriendlySequences]

Design Thinking:
The problem requires counting subarrays where numbers have the same set of digits. To represent this efficiently, I converted each number into a frequency vector (boolean array of size 10) marking which digits appear. As I iterated through the array, I compared each number’s digit-set with the previous one. If they matched, I extended the current sequence; otherwise, I ended the sequence and added the count of possible subsequences from the accumulated segment.

Troubleshooting:
Initially, I used a simple counter but realized I was not properly accumulating subsequences from each block. To fix this, I applied the combinatorial formula total * (total - 1) / 2 to count all pairs within a segment. Another challenge was handling the transition between segments: when moving to a new digit-set, I reset the counter and updated the result.

Reflection:
This problem reinforced the usefulness of representing properties with compact data structures (like a boolean digit presence vector). By carefully handling segment boundaries and using a combinatorial formula, I was able to reduce the problem to O(N × D) complexity (where N is array length and D = 10). This ensured efficiency even for large input sizes.


Weekly Reflection

This week, I worked on four problems: MonsterValley2, UnsealTheSafe, PaternityTest, and FriendlySequences. Each of these problems required different approaches, and collectively, they gave me a deeper understanding of recursion, dynamic programming, greedy methods, and combinatorial counting.

From MonsterValley2, I learned how recursion naturally models decision-making problems, but I also realized the limitation of exponential complexity. This pushed me to think more critically about optimization and efficiency.

UnsealTheSafe highlighted the transition from recursion to dynamic programming. At first, my recursive solution led to inefficiency, but by applying memoization and later a bottom-up DP, I was able to significantly reduce time complexity. This problem solidified my understanding of how overlapping subproblems can be leveraged in DP.

In PaternityTest, I practiced applying a greedy strategy to a string-matching problem. I saw the importance of carefully handling edge cases, especially when overlaps between the mother and father’s DNA could cause incorrect results. This problem showed me how greedy solutions, when structured properly, can provide both efficiency and correctness.

Finally, FriendlySequences taught me how compact representations (like a boolean digit presence vector) can simplify the problem-solving process. By breaking sequences into segments and applying combinatorial formulas, I learned how to count efficiently without iterating over all subarrays.

Overall, this week helped me strengthen my problem-solving toolkit. I gained experience in recognizing when recursion is appropriate versus when DP is necessary, how to apply greedy methods with careful checks, and how to use mathematical formulas to optimize counting. These skills will be valuable as I continue practicing and tackling more complex problems.
